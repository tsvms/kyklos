Kyklos is free. It has no accounts, no ads and no tracking, and everything stays on your phone in SQLite.
It's one Expo codebase (React Native, TypeScript, Expo Router, SDK 57). The name is Kyklos, the slug is `kyklos`, the bundle ID / package is `com.kyklos.app` and the version is 1.1.0.

## Features

- **Streak fire 🔥.** The Today screen opens on your streak: the days in a row on which you completed at least one habit.
  - The fire has three states. **Lit** means done today, and it glows and flickers. **Waiting** (dimmed) means yesterday was kept but today is still open. **Out** (grey ash) means the streak is broken.
  - Each habit has its own small fire and count in the list, too.
- **Ranks.** Ten ranks, one for each streak length: Coal → Spark (1) → Flame (3) → Blaze (7) → Torch (14) → Beacon (30) → Volcano (60) → Phoenix (100) → Sun (200) → Olympian (365).
  - A gradient bar shows how far you are from the next rank, and a toast celebrates each rank-up.
  - Stats shows the full ladder. Your best streak unlocks each rank for good.
- **Add, edit and delete on the home screen.** Use the ✎ button (edit mode, with a bin on every habit), long-press a habit for its actions, or tap the dashed "Add a habit" card.
- **Today.** A 7-day strip of mini rings shows each day's progress. Tap a past day to fill in a check-in you forgot. Check-ins give haptics and update instantly.
- **Schedules.** Every day, X times per week, specific weekdays, or every N days, with an optional local reminder for each habit.
- **Times a day.** A habit can need several check-ins a day (e.g. 6 glasses of water). Its circle becomes a counter: tap adds one and a ring fills, long-press takes one back. The day counts once the target is reached.
- **Habit detail.** Streak hero, 30-day rate, total check-ins, a 17-week heatmap, and Edit / Archive (keeps the history) / Delete.
- **Stats.** Day streak, best streak, this week, 30-day rate, 8 weekly bars, the fire for each habit, and the rank ladder.
- **Settings.**
  - Light / dark / system theme. The app is English-only.
  - Reminders, plus JSON export / restore and delete all data.
  - Archived habits, and the privacy policy, terms and licences.
- **Design.**
  - A warm palette with an ember accent and a floating frosted tab bar.
  - The streak card is cream by day and ember-dark by night.
  - Habit names in Greek keep their leading accent on Android (it is otherwise clipped when a line is truncated).

## Legal & privacy

- **The app collects nothing.** It makes no network requests and has no analytics, ads or accounts. The App Store label is *Data Not Collected*; Play Data safety is *No data collected*.
- **One repo, one site.** The public pages live in [`docs/`](docs) and are served by GitHub Pages at **https://tsvms.github.io/kyklos/**.
- **The texts come from one source.** The in-app privacy policy and terms and the public pages both come from `lib/i18n/index.ts` + `lib/legal.ts`. Running `npm run legal` regenerates `docs/*.html`, `PRIVACY.md` and `TERMS.md`, so they can never drift apart.
- **GDPR rights map to features:** access and portability (Export), rectification (Edit), erasure (Delete all data or uninstall).
- **iOS privacy manifest:** configured in `app.json`.
- **LICENSE:** free to download and use. The source is published for transparency, and all rights are reserved for the app itself; see [LICENSE](LICENSE). The third-party MIT and public-domain components are listed in the app.
- **Publisher:** Lumena, lumenateam@gmail.com (set in `lib/legal.ts`). See **[STORE_LISTING.md](STORE_LISTING.md)** for every store form answer and the listing text.

## 1. Setup from zero

You need **Node.js 20 or newer** (LTS). Check with `node -v`. Everything else is installed by the commands below.

```bash
cd Kyklos
npm install
npm test             # unit tests (schedule, streaks, milestones, backup validation, daily counts)
npm run typecheck    # npx tsc --noEmit — should print nothing
```

Install the EAS CLI once, globally:

```bash
npm install -g eas-cli
eas --version
```

(If you'd rather not install globally, put `npx eas-cli@latest` wherever this README says `eas`.)

---

## 2. Free quick preview: Expo Go

1. On your phone, install **Expo Go** from the Play Store or App Store. It must support **SDK 57**, which the current store version does.
2. On the computer, run:

   ```bash
   npm start            # = npx expo start --go
   ```

3. Scan the QR code:
   - **Android:** use the scanner inside Expo Go.
   - **iPhone:** use the Camera app, then tap the banner.

The phone and computer must be on the same Wi-Fi. If they can't be, run `npx expo start --go --tunnel` instead.

> **Why `--go`?** The project includes `expo-dev-client` so development builds work. Without `--go`, `expo start` would expect a development build rather than Expo Go.

**Limitations of Expo Go.** Everything works except reminders, which are unreliable there. **On iOS in particular, notifications may not fully work in Expo Go.** For full testing, use a development build:

```bash
eas device:create                               # iPhone only, once: register the device's UDID
eas build -p ios --profile development          # or: eas build -p android --profile development
npm run start:dev                               # = npx expo start --dev-client
```

Install the development build from the link or QR code EAS gives you, open it, and it connects to your dev server.

## 4. Android: installable APK (free, no store)

## 5. Android: Play Store bundle (AAB)

```bash
eas build -p android --profile production
```

This produces an `.aab`, with `versionCode` auto-incremented by EAS. To publish:

1. Create a Google Play Console account ($25 one-time) at <https://play.google.com/console>.
2. Go to **Create app**, choose name "Kyklos", app, free, then fill in the declarations.
3. The first upload has to be manual. Go to **Testing → Internal testing → Create new release** and upload the `.aab`.
4. For later uploads you can use `eas submit -p android --latest`. This needs a Google service-account JSON key; EAS explains how to create one the first time you run it. The submit profile sends builds to the **internal** track as a draft.

## 6. iPhone: TestFlight

### What you honestly need

- A **paid Apple Developer Program membership: $99/year**, enrolled at <https://developer.apple.com/programs/enroll/>. Approval takes from minutes to about 48 h. Without it you cannot put the app on a real iPhone outside Expo Go.
- The bundle ID **`com.kyklos.app`**. EAS registers it in your Apple account automatically during the first build. If someone else already owns that ID, change `ios.bundleIdentifier` in `app.json` (for example to `com.<yourname>.kyklos`).
- **You do not need a Mac.** EAS builds in the cloud.

### Build

```bash
eas build -p ios --profile preview
```

Answer the prompts:

1. **"Do you want to log in to your Apple account?"** Answer **Yes** and enter your Apple ID, password and 2FA code.
2. **Register bundle identifier / generate a Distribution Certificate / generate a Provisioning Profile:** answer **Yes** to each. EAS creates and stores them.
3. **Push notifications key:** you can answer **No**. Kyklos uses local notifications only.

This builds a store-signed `.ipa`, which is what TestFlight needs.

### Create the app in App Store Connect (every click)

1. Go to <https://appstoreconnect.apple.com> and sign in.
2. Click **Apps**, then the blue **+** (top left), then **New App**.
3. Fill in the form:
   - **Platforms:** ☑ iOS
   - **Name:** `Kyklos`. It must be unique on the App Store; if it's taken, use something like `Kyklos – Habits`. This is only the store name; the home-screen name stays "Kyklos".
   - **Primary Language:** English (U.S.)
   - **Bundle ID:** pick `com.kyklos.app` from the dropdown. It appears after the first EAS build, or after `eas credentials`.
   - **SKU:** `kyklos-001` (any text you like)
   - **User Access:** Full Access
4. Click **Create**.

### Submit to TestFlight

```bash
eas submit -p ios --latest
```

Log in with your Apple ID again and choose the Kyklos app. The first time, let EAS **generate an App Store Connect API key**. The upload takes a few minutes, and Apple then processes the build for another **5–30 min**.

### Internal testing (every click)

1. In App Store Connect, go to **Apps → Kyklos → TestFlight** (tab at the top).
2. The build appears under **iOS Builds**. Wait until its status changes from *Processing* to *Ready to Submit* / *Ready to Test*. There's no export-compliance question to answer, because `ITSAppUsesNonExemptEncryption` is already `false`.
3. In the left sidebar, under **Internal Testing**, click **+**, name the group (for example `Team`), then click **Create**.
4. In that group, go to **Testers → +** and pick people. Internal testers must already be users of your team (**Users and Access**). The Account Holder, which is you, already is.
5. In the group, go to **Builds → +**, select the build, then click **Add**.
6. On the iPhone, install **TestFlight** from the App Store and open the invitation email (or just open TestFlight). Tap **Install** next to Kyklos.

Later versions: run `eas build -p ios --profile preview`, then `eas submit -p ios --latest`. The build number increments automatically.

## 7. Troubleshooting

**Android 12+ reminders arrive late or not at the exact minute.**
Since Android 12, exact alarms need `SCHEDULE_EXACT_ALARM`, and on Android 14+ it is *off by default* for newly installed apps. Kyklos still schedules its reminders, but Android may deliver them a few minutes late. To make them exact, go to **Settings → Apps → Kyklos → Alarms & reminders → Allow**. Also, on Samsung, Xiaomi, Huawei and similar phones, set **Battery → Unrestricted** for Kyklos, because aggressive battery savers can delay or drop notifications. After a phone reboot, the notification library restores scheduled reminders by itself (that's what `RECEIVE_BOOT_COMPLETED` is for), and Kyklos also re-plans everything each time it opens.

**Why there is no `USE_EXACT_ALARM`.**
Google Play restricts `USE_EXACT_ALARM` to alarm-clock and calendar apps, so `app.json` blocks it. `SCHEDULE_EXACT_ALARM` alone is enough.

**How reminders are planned.**
Kyklos schedules each reminder as a concrete date up to 14 days ahead. It re-plans on every launch and after every change. This is how it skips a day you've already completed, stops a weekly habit once you hit the target, and supports "every N days". If you don't open Kyklos for two weeks, reminders pause on purpose: a quiet app shouldn't nag a habit you've set aside. Opening the app resumes them.

**Android 13+: no notification prompt.**
Android only shows the prompt after the app has created a notification channel, and Kyklos creates one right before asking. If you pressed "Don't allow", go to **Settings → Apps → Kyklos → Notifications**.

**iOS: I denied notifications.**
iOS asks only once. After that, Kyklos shows a gentle "Open settings" button (Today banner, Settings tab and the habit form). Or go to **Settings → Kyklos → Notifications → Allow Notifications**.
Note: Apple doesn't allow custom text in the notification permission prompt. Its wording is fixed by iOS, localized to the phone's language. Kyklos's own explanation is shown in the Settings tab.

**iOS: reminders don't fire in Expo Go.**
This is expected. Use a development build (`eas build -p ios --profile development`) or TestFlight.

**`eas: command not found` / `'eas' is not recognized`.**
Run `npm install -g eas-cli` and open a new terminal, or use `npx eas-cli@latest <command>`.

**`eas build` says "not logged in" or "project not configured".**
Run `eas login`, then `eas whoami`, then `eas init`. On CI, set an `EXPO_TOKEN` (from expo.dev → Account settings → Access tokens) instead of logging in.

**Expo Go says the project is incompatible or needs a newer SDK.**
Update Expo Go from the store. This project is SDK 57.

**Metro cache weirdness after changing config.**
Run `npx expo start --go --clear`.

**Dependency sanity check.**
Run `npx expo-doctor`; every check should pass.

**Build profiles in `eas.json`**

| Profile | Android | iOS |
| --- | --- | --- |
| `development` | dev-client APK | dev-client (internal, registered devices) |
| `preview` | **APK**, internal link / QR | **store-signed IPA** for TestFlight |
| `production` | **AAB** for Play Store | store-signed IPA |

**Data.** SQLite (`kyklos.db`) holds the `habits`, `checkins` and a small `settings` table (theme). Dates are local `YYYY-MM-DD` strings, so a check-in belongs to the calendar day you made it on. Reminders are rebuilt from the database on every launch and after every change, so killing and reopening the app keeps both data and reminders.

**Permissions.** Android declares `RECEIVE_BOOT_COMPLETED`, `SCHEDULE_EXACT_ALARM` and `VIBRATE`, and blocks `USE_EXACT_ALARM` plus storage, camera, microphone and overlay permissions. Two more end up in the final manifest on purpose. `INTERNET` comes from the React Native template and the development build needs it to reach Metro. `POST_NOTIFICATIONS` is merged by `expo-notifications`, and without it Android 13+ can't show notifications.
